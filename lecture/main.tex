  \section{Introduction}
  In this tutorial, we will implement a server and client using the Python programming language.
  In this program, after connecting to the server, the client sends a text message to it.
  The server receives the text and sends it back to the client. Upon receiving the text again, the client prints the received message and closes the connection.
  Such tools are called \textbf{Echo} servers, which were historically used to verify connection integrity.
  At the end, we will have a brief overview of the \textbf{UDP} protocol, which unlike \textbf{TCP}, provides connectionless communication.

  \section{Echo Server}

  The server code is as follows. Each section of the code is explained in detail below.

  \begin{minted}[bgcolor=LightGray]{python}
import socket

HOST = '127.0.0.1'  # Standard loopback interface address (localhost)
PORT = 1373         # Port to listen on (non-privileged ports are > 1023)

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.bind((HOST, PORT))
    s.listen()
    conn, addr = s.accept()
    with conn:
        print('Connected by', addr)
        while True:
            data = conn.recv(1024)
            if not data:
                break
            conn.sendall(data)
  \end{minted}

  First, we create a socket. The following code is used to create a socket:

  \begin{minted}[bgcolor=LightGray]{python}
socket.socket(socket.AF_INET, socket.SOCK_STREAM)
  \end{minted}

  The first argument to the \texttt{socket} function specifies the address family, and the second specifies the type of data transfer in the connection.
  In this example, by selecting \texttt{AF\_INET}, we choose IPv4 addressing.
  If we want to use either IPv4 addresses or hostnames, we must pass this address type to the function.
  \texttt{SOCK\_STREAM} is used for communication over the TCP protocol.
  If we want to change the transport layer protocol, we use this argument.
  Other address families include \texttt{AF\_PACKET}, \texttt{AF\_INET6}, \texttt{AF\_CAN}, and \texttt{AF\_BLUETOOTH}.

  After creating the socket, we assign an address to it.
  The address given to the socket is the address from which the socket receives and sends data.
  The address consists of two parts: \texttt{host} and \texttt{port}.
  The \texttt{host} is a string that specifies which network interface to listen on, and the \texttt{port} specifies the port number the server listens on.
  The \texttt{host} value, depending on the address type, can be an IPv4 address, a hostname, or an empty string.
  If an empty string or \texttt{"0.0.0.0"} is set as the host, the server will use all available network interfaces for communication.
  Finally, with this information specified, we want the socket to enter the listening state to accept requests.

  The input parameter to the \texttt{listen} function, called \texttt{backlog}, specifies the number of unaccepted connections that the operating system will allow before refusing new connections.
  This number allows your application to delay accepting requests for various reasons.
  Since Python 3.5, this parameter is optional, and if not specified, a reasonable default value is used.

  \begin{minted}[bgcolor=LightGray]{python}
s.bind((HOST, PORT))
s.listen(1)
  \end{minted}

  After specifying the address information, the socket must wait for a connection from the client.
  When the program reaches the following code, it stops and waits to receive a connection request from a client.
  After receiving a connection request, the server confirms the request by calling the following code.
  After confirming the request, the requester's address and the established connection are stored in the \texttt{addr} and \texttt{conn} variables.

  \begin{minted}[bgcolor=LightGray]{python}
conn, addr = s.accept()
  \end{minted}

  Now that the connection is established, data transfer is possible.
  The server reads a specified amount of data each time. In this example, a \textbf{maximum} of 1024 bytes of data is read each time.
  In practice, when designing a protocol, you need a method to identify each request. For example, you can terminate each request with the \texttt{'\textbackslash n'} character.
  In this case, you must search the received array for this character. If the character is found, save the rest of the array for the next iteration.
  If the character is not found, you must wait for the next read. Keep in mind that higher-level libraries exist to simplify these operations.

  \begin{minted}[bgcolor=LightGray]{python}
with conn:
    print('Connected by', addr)
    while True:
        data = conn.recv(1024)
        if not data:
            break
  \end{minted}

  Here, we don't follow any specific protocol, so after reading the data, we simply send it back to the client.

  \begin{minted}[bgcolor=LightGray]{python}
conn.sendall(data)
  \end{minted}

  \section{Echo Client Using Telnet}

  After creating the server, we need to create a client to communicate with it.
  One simple way to test the server before implementing a client is to use the \texttt{telnet} command in Linux.
  (This command is also available on other operating systems.)
  The simplified structure of this command is as follows:

  \begin{minted}[bgcolor=LightGray]{bash}
telnet [ip] [port]
  \end{minted}

  The \texttt{telnet} command establishes a TCP connection with the given IP address and port.
  You can write whatever you want in this connection and send it to your destination by pressing Enter.
  The data received from the server will also be displayed.

  Note that your server only performs the \texttt{accept} operation once, so after the first client's connection closes, your server terminates.
  To prevent this, the \texttt{accept} function call is usually placed in an infinite loop.

  \begin{minted}[bgcolor=LightGray]{python}
import socket

HOST = '127.0.0.1'  # Standard loopback interface address (localhost)
PORT = 1373         # Port to listen on (non-privileged ports are > 1023)

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.bind((HOST, PORT))
    s.listen()
    while True:
      conn, addr = s.accept()
      with conn:
          print('Connected by', addr)
          while True:
              data = conn.recv(1024)
              if not data:
                  break
              conn.sendall(data)
  \end{minted}

  In this case, your server will never close, and you can connect to it multiple times.

  \subsection{Adding Threads}

  If we want to support many clients simultaneously using a single server, we need to use threads.
  Python has many standard libraries for using threads. One library that is very similar to Java is the \texttt{threading} library.

  \begin{minted}[bgcolor=LightGray]{python}
import socket
import threading
from typing import Tuple

class Client(threading.Thread):
    def __init__(self, conn: socket.socket, addr: Tuple[str, int]):
        super().__init__(name=f'client {addr}')
        self.conn = conn

    def run(self):
        with self.conn:
            while True:
                data = self.conn.recv(1024)
                if not data:
                    break
                self.conn.sendall(data)

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.bind(("0.0.0.0", 1234))
    s.listen()
    while True:
        conn, addr = s.accept()
        print(f'connected by {addr}')
        Client(conn, addr).start()
  \end{minted}

  To use this library, one approach is to define a class that inherits from \texttt{Thread}, create an instance of it, and start a new thread with the \texttt{start} method, which runs the \texttt{run} method.

  \section{Echo Client}

  \begin{minted}[bgcolor=LightGray]{python}
import socket

HOST = '127.0.0.1'  # The server's hostname or IP address
PORT = 1373         # The port used by the server

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.connect((HOST, PORT))
    s.sendall('hello world'.encode())
    data = s.recv(1024)
    message = data.decode()
    print(f'received {message!r}')
  \end{minted}

  Like the server, we first need to create a socket with the same properties as the socket created on the server:

  \begin{minted}[bgcolor=LightGray]{python}
socket.socket(socket.AF_INET, socket.SOCK_STREAM)
  \end{minted}

  After creating the socket, we give it the server's address to send a connection request.
  The code blocks at this line until the connection request is accepted, rejected, or times out.
  If the request is not accepted, the program raises an error and stops.
  Make sure that when using this socket in applications, errors due to connection failures do not crash your main program.
  If the connection is confirmed, the program continues.

  \begin{minted}[bgcolor=LightGray]{python}
s.connect((HOST, PORT))
  \end{minted}

  To handle errors, you can use Python's \texttt{try/except} structure:

  \begin{minted}[bgcolor=LightGray]{python}
try:
    with open('file.log') as file:
        read_data = file.read()
except:
    print('Could not open file.log')
  \end{minted}

  \begin{minted}[bgcolor=LightGray]{python}
try:
    with open('file.log') as file:
        read_data = file.read()
except FileNotFoundError as fnf_error:
    print(fnf_error)
  \end{minted}

  The following code sends the string "Hello World" to the server. Note that using the \texttt{encode} function allows you to convert UTF-8 strings to byte strings for transmission.

  \begin{minted}[bgcolor=LightGray]{python}
s.sendall('Hello, world'.encode())
  \end{minted}

  After sending the data, like the server part, we wait to receive data. Note that in practice, one of the parties must terminate the connection.
  For example, we can close the connection on the client side after ensuring correct receipt of the string, or the user can close the client and connection with \texttt{Ctrl + C}.

  \begin{minted}[bgcolor=LightGray]{python}
while True:
  data = conn.recv(1024)
  if not data:
      break
  \end{minted}

  \section{UDP-Based Communication}
  Python allows you to broadcast data using the UDP protocol.
  In the following example, a UDP client is created to send broadcast messages.
  This client binds to address \texttt{0.0.0.0} and port \texttt{44444} and uses it to receive UDP packets.
  This client sends packets to the broadcast address on port \texttt{37020}.
  Note that in both clients, we have configured the broadcast mode settings.

  \begin{minted}[bgcolor=LightGray]{python}
import socket
import time

server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
server.settimeout(0.2)
server.bind(("", 44444))
message = b"your very important message"
while True:
    server.sendto(message, ('255.255.255.255', 37020))
    print("message sent!")
    time.sleep(1)
  \end{minted}

  The second client binds to address \texttt{0.0.0.0} and port \texttt{37020} and receives data.
  Here, like TCP communication, we must specify the maximum received data, but keep in mind that if the received packet contains more data than specified, this extra data \textbf{will be lost}.

  \begin{minted}[bgcolor=LightGray]{python}
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_DGRAM) # UDP
client.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
client.bind(("", 37020))
while True:
    data, addr = client.recvfrom(1024)
    print("received message:", data, addr)
  \end{minted}

  The main difference between TCP and UDP communication is in how the socket is created and the functions for sending and receiving data.
  Of course, from your networking course, you remember that in UDP communication, no connection is formed, and data reaches the application in the form of messages.
  These messages may be out of order or contain errors.
